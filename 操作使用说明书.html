01

认识 PM-Workstation

项目定位 · 核心特性 · 架构

PM-Workstation 是一款基于多 Agent 流水线架构的产品经理通用项目工作站。它通过一个总指挥 Agent 调度多个专业 Agent，覆盖知识库管理、需求文档编写、原型设计、版本管理、原型复原、UI 规范维护全链路工作。

1.1 五大核心特性

🤖

多 Agent 协作

总指挥 Orchestrator 统一调度 6 个 Agent，每个 Agent 内部含独立子流水线，按阶段串行推进。

📦

版本隔离

一个需求 = 一个版本，格式 {名称}_v{主}.{次}.{补丁}，各版本产出物互不干扰。

🔄

原型复原

从线上页面 URL 一键复原为可交互原型：计划 → 爬取 → 验证，匹配度 ≥90% 方可交付。

⚡

零构建依赖

所有原型与文档产物为纯 HTML/CSS/JS，无需 npm/webpack，浏览器双击即可打开。

✅

全流程检验

每条流水线设质量门禁与评分通过线，机器可验与人工判定结合，返工最多 2 次。

🧠

用户认知系统

自动记忆用户偏好与反馈，反馈阈值 2 次即固化，记忆保留 90 天，输出前自动检查偏好。

1.2 多 Agent 架构总览

工作站采用"1 个总指挥 + 5 个业务 Agent"的调度架构。用户只需用自然语言提出需求，由总指挥解析意图、匹配任务类型、调度对应 Agent 执行，并负责版本上下文管理、Git 提交、状态同步。

Agent角色职责
Orchestrator总指挥意图解析、版本上下文、任务分解、调度监控、Git 提交、状态刷新
PRD-Agent需求工程师编写产品需求文档（PRD），含调研→图先行→撰写→可行性→评审
Proto-Agent原型工程师交互原型设计，含设计→实现→测试，UI 规范引用映射
Restore-Agent复原工程师线上页面复原为可交互原型，抓取现有代码不重新编码
KB-Agent知识库管家知识条目创建、爬虫文档归档、内容审核
UI-Standard-AgentUI 规范管理员线上实测收录 UI 控件规范，维护 UI-xx 编号库

6 个 Agent 职责详解

3.1 Orchestrator · 总指挥

中枢调度角色，不执行具体业务任务，只负责解析意图、调度 Agent、汇总结果。每次启动必执行 git pull（有远程仓库时）。

核心职责：意图解析 → 版本上下文提取 → 用户认知加载 → 任务分解（生成 task_id）→ 波次规划 → 生成任务书 → 调度监控 → 阻塞处理 → 汇总检验 → Git 提交 → 状态刷新。

注：版本操作（创建/切换/对比/归档）与组件模版管理由总指挥直接执行，不调度 Agent；业务任务（PRD/原型/复原/KB/UI 规范）才调度对应 Agent。

操作流程

启动序列 · 双卡点流程 · 多任务

5.1 启动序列

每次启动工作站，总指挥按以下 4 步顺序执行。步骤 0 为环境硬门禁，未通过不得继续。

图 5-1：启动序列四步。步骤 0 为环境硬门禁（橙色），失败则进入首次安装流程；通过后依次读取状态与配置，最终进入意图分类（绿色）。

5.2 文件变更双卡点流程

任何涉及文件编辑的任务，严格按双卡点流程执行，禁止跳步。两个卡点均需用户明确信号词方可放行。

图 5-2：文件变更双卡点流程。红色菱形为强制卡点，未获用户明确信号词不得放行。

卡点信号词判定

卡点放行信号词（命中任一即通过）不算放行
卡点①
计划批准		批准 · 可以 · 执行 · 开始 · OK · 确认 · 没问题 · 按这个来 · 就这么办仅补充需求 · 纠正 · 疑问 · 只读不回 · 语气词（嗯/哦）
卡点②
审查通过		通过 · 审查通过 · 没问题 · OK · 可以 · 确认提出修改意见 · 指出遗漏 · 只读不回
红线

卡点①批准前禁止任何写操作；卡点②通过前禁止 state refresh。审查不通过时，基于已提交内容继续修改，走新的「计划→执行→commit→审查」循环。

5.3 多任务组合

  • 串行（默认）：子任务按声明顺序逐个执行
  • 波次并行：任务书声明 wave 字段后，同 wave 步骤可并行调度
  • 典型并行场景：restore + kb（无依赖）、proto + prd（proto 有 restored 页面时）
  • 失败传播：前一子任务 BLOCKED，后续全部跳过
  • 典型 multi 顺序：restore → proto → prd

07

版本管理

模型 · 操作 · 两处同步

7.1 版本模型

一个需求 = 一个版本。格式为 {名称}_v{主版本}.{次版本}.{补丁}，例如 库存调拨_v1.0.0。名称只允许中英文、数字、下划线、连字符。同名需求下，次版本号自动 +1。

7.2 版本操作

操作命令/方式说明
创建/manage-version 创建 库存调拨自动计算版本号，创建目录骨架
切换/manage-version 切换 库存调拨_v1.0更新 current_version
状态/manage-version 状态查看版本进度、PRD/原型文件、任务记录
对比version_manager.py diff v1 v2对比两个版本的文件差异
列表version_manager.py list列出所有版本
归档version_manager.py archive归档版本（需两处同步）
规则 W25

两处同步：创建与归档版本时，必须同步两处——config/project.yaml 的 version.versions 列表 与 STATE.md 版本表。可通过 python3 scripts/state_manager.py refresh 自动同步。

注意

创建新版本但未提供名称时，总指挥必须先询问用户，禁止自行编造版本名。用户未指定版本时，用 version_manager.py list 展示供选择。

8.2 检验清单要点

每次任务必检通用项 7 条 + 各任务类型专项检验。每项标注【机器可验】（附检查命令）或【人工判定】（附判定要点），机器可验占比目标 ≥60%。

通用检验 7 条

  • 代码已同步（git rev-parse HEAD = origin/main）
  • 任务书存在且字段完整
  • Agent 输出文件存在
  • 阻塞已解决
  • 最终报告含交付物清单
  • 用户可定位产出
  • 版本上下文正确

8.3 返工上限

规则 W20

任何自动返工循环统一最多 2 次（首次执行 + 2 次返工 = 3 次尝试）。仍未通过则暂停流水线，向用户报告，禁止无限重试。PRD HTML 生成后必过 prd_html_check.py 6 类断言（W27），任一 FAIL 不得 commit。

09

常见问题

FAQ
首次使用，环境自检失败怎么办？
环境自检（check_env.py）任一项 FAIL 即判定首次使用。总指挥会展示安装清单，等待你同意后按 INSTALL.md §3 执行安装（pip 依赖 / hooks 赋权 / settings.json 路径替换 / 目录修复），完成后重跑自检验收。验收未通过前禁止进入工作流程。注意 Python 需用户自行安装（≥3.9），Agent 不可代装。
我不知道该用什么命令，怎么说才对？
直接用自然语言描述需求即可，例如"写一份库存调拨的 PRD""复原这个页面"。总指挥会自动匹配任务类型。如果输入未命中任何任务类型，会展示 10 类候选意图供你选择（规则 W16），不会自行猜测路由。
系统一直等着我确认计划，我该说什么？
这是卡点①（计划批准）。放行信号词：批准 / 可以 / 执行 / 开始 / OK / 确认 / 没问题 / 按这个来 / 就这么办。如果你只是补充需求、纠正或提出疑问，不算批准，系统会修订计划后继续等待。详见规则 W13。
变更做完后审查怎么算通过？
这是卡点②（审查通过）。通过信号词：通过 / 审查通过 / 没问题 / OK / 可以 / 确认。如果你提出修改意见或指出遗漏，不算通过，系统会基于已提交内容继续修改。通过后才执行 state_manager.py refresh。详见规则 W15。
没指定版本会怎样？
若只说需求名称（如"库存调拨"），系统匹配该名称的最新版本；若完全未指定，会调用 version_manager.py list 展示版本列表供你选择；若要创建新版本但未提供名称，系统必须先询问你，禁止自行编造版本名。
原型/PRD 评审没过怎么办？
系统会自动返工，最多重试 2 次（首次 + 2 次返工 = 3 次尝试，规则 W20）。仍未通过则暂停流水线并向你报告。各流水线通过线：PRD ≥80、原型 ≥90、复原 ≥90（80-89 有条件通过需你确认）、操作文档 ≥85、知识库 ≥90。
HTML 里的流程图为什么是交互式的？
项目规则（flow-diagram-standard.md S01）要求所有 HTML 产物中的流程图禁止静态 PNG，必须使用 flowdia 交互组件（Mermaid 为 Markdown 权威源）。悬停节点可高亮上下游链路。本说明书的启动序列与双卡点流程图为简洁线性示意，采用内联 SVG 绘制以保持零依赖。
项目里那么多规则编号（W/D/F/UI…）是什么？
项目采用编号化规则体系确保执行零猜想。主要前缀：W（SOP 编写规范，W01-W32）、F（PRD 格式，F01-F11）、D（PRD 图绘制，D01-D08）、S（流程图标准，S01-S09）、OD（操作文档，OD01-OD14）、UI（UI 规范，UI-xx）、H（HTML 渲染，H01-H07）。完整定义见 docs/rules/sop-writing-standard.md §2.5 编号前缀注册总表。
产出文件存在哪里？
版本产物存于 versions/{版本号}/（含 prd/、prototype/、agent_comm/ 等子目录）；操作文档独立存于项目根 operation_docs/；知识库存于 docs/knowledge-base/；UI 规范存于 docs/rules/ui-standard/。跨会话状态记录在根目录 STATE.md。
