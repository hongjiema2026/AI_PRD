## 一、环境搭建（一次性操作）

```bash
# 1. 进入项目目录
cd ~/Desktop/PM-Workstation

# 2. 创建虚拟环境
python3 -m venv .venv
source .venv/bin/activate    # macOS
# .venv\Scripts\activate     # Windows

# 3. 安装依赖
pip install -r requirements.txt
pip install -r requirements-dev.txt

# 4. 验证安装
python3 -m pytest tests/ -v
```

如果全部 PASS，环境就搭好了。后续每次使用只需要：

```bash
cd ~/Desktop/PM-Workstation
source .venv/bin/activate
```

## 二、日常使用：用自然语言提需求

在当前 AI 工具中直接用自然语言提出需求即可，系统会自动识别任务类型并走对应流水线。任务路由共 8 类单任务 + 1 类组合任务：

| 任务类型 | 触发示例 | 主要产出 |
|----------|----------|----------|
| prd | "写一份购物车优化的 PRD" | `versions/{版本}/prd/{功能名}-prd.md` |
| proto | "根据购物车 PRD 出原型" | `versions/{版本}/prototype/proto-*.html`（平铺） |
| restore | "复原这个线上页面做参考" | `versions/{版本}/prototype/restored/{域名}_{时间戳}/` |
| kb | "把这份竞品资料入库" | `docs/knowledge-base/{类型}/` + 索引更新 |
| version | "新建一个版本做库存预警" | `versions/{版本}/` 目录骨架 |
| doc | "根据原型写操作手册" | 版本内操作文档（Markdown + docx） |
| diagram | "画一张库存调拨的流程图" | flowdia 交互图 |
| component | "做个可复用的数据表格组件" | `templates/components/` 组件模版 |
| multi | "写 PRD 然后出原型" | 按顺序调度多个 Agent |

下面 5 个典型场景覆盖最常用的用法。

### 场景 1：写一份新 PRD

> "帮我写一份购物车优化的 PRD，目标是降低结算页跳出率 15%"

流水线：调研 → 图先行 → 撰写 → 可行性验证 → 评审 → 你确认后生成 HTML 渲染版。产出：

- PRD 正文 → `versions/{版本}/prd/{功能名}-prd.md`
- 评审报告 → `versions/{版本}/agent_comm/{任务ID}/05_prd_review_report.md`（评分 ≥80 才通过）
- HTML 渲染版 → `versions/{版本}/prd/{功能名}-prd.html`（你确认 Markdown 后才生成）

### 场景 2：根据 PRD 做原型

> "根据刚写的购物车 PRD 出原型"

流水线：架构设计 → 代码实现 → 交互测试。产出：

- 设计文档 → `versions/{版本}/prototype/{功能名}-prototype.md`
- 组件原型 → `versions/{版本}/prototype/proto-*.html`（平铺在 prototype/ 下，浏览器直接打开）
- 组装页面 → `versions/{版本}/prototype/{功能名}-prototype.html`
- 测试报告 → `versions/{版本}/agent_comm/{任务ID}/03_proto_test_report.md`（评分 ≥90 才通过）

### 场景 3：复原一个线上页面作为参考

在终端执行：

```bash
# 无需登录
python3 scripts/restore_pipeline/main.py https://某个网站.com/页面

# 需要登录
python3 scripts/restore_pipeline/main.py https://某个网站.com/页面 \
  --username your_name --password your_pass

# 或用 Cookie
python3 scripts/restore_pipeline/main.py https://某个网站.com/页面 \
  --cookie "session_id=xxx; token=yyy"
```

复原结果在 `versions/{版本}/prototype/restored/` 下，浏览器打开 `index.html` 即可查看。验证报告 → `versions/{版本}/agent_comm/{任务ID}/03_restore_verification.md`。

### 场景 4：管理版本

```bash
# 查看所有版本
python3 scripts/version_manager.py list

# 查看当前版本
python3 scripts/version_manager.py current

# 发布版本
python3 scripts/version_manager.py release v0.1.0
```

也可以直接用自然语言："新建一个版本做库存预警"、"切换到 v0.2"。

### 场景 5：多任务组合

一句话发复杂需求，系统会自动拆解并按顺序执行：

> "帮 XX 平台的库存调拨功能写 PRD，然后出原型，最后复原 XX 的库存管理页面做参考"

## 三、版本目录结构

每个版本（`versions/{版本}/`）的标准结构：

```
versions/{版本}/
├── prd/                          ← PRD Markdown + HTML 渲染版
├── prototype/
│   ├── proto-*.html              ← 组件原型（平铺）
│   ├── {功能名}-prototype.html   ← 组装页面
│   └── restored/                 ← 复原的线上页面
├── agent_comm/{任务ID}/          ← Agent 过程产物（调研/评审/测试报告等）
└── CHANGELOG.md
```

历史版本的旧目录结构（如 `prototype/pages/`）保留不迁移，以现行结构为准。

## 四、常用命令速查

| 命令 | 说明 |
|------|------|
| `make install-dev` | 安装所有依赖 |
| `make test` | 运行测试 |
| `make test-cov` | 运行测试 + 覆盖率报告 |
| `make lint` | 代码检查 |
| `make format` | 格式化代码 |
| `make check` | lint + format + test 全检查 |
| `make help` | 查看所有命令 |

如果不用 Makefile，等效命令：

```bash
pip install -r requirements-dev.txt
PYTHONPATH=scripts:scripts/restore_pipeline:scripts/utils python3 -m pytest tests/ -v
```
