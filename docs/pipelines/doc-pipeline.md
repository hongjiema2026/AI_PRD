> 本文件是**操作文档流水线的唯一权威定义**：目录结构、编写规则明细（OD01-OD14）、执行流程、检验清单。规则编号 OD01-OD14 只在本文件 §3 定义一次，其他文档只写「引用规则 ODxx」（注册见 `docs/rules/sop-writing-standard.md` §2.5）。评审评分维度权威定义见 `docs/verification/quality-gates.md` §2.4（≥85 通过，本文件不重述，引用规则 W01）。

## §1 目的与适用范围

操作文档由 Orchestrator 直接执行，利用 **Playwright** 进入真实页面截图，结合用户输入的功能点生成操作手册，最终交付 docx。

**重要：操作文档完全独立于 `versions/`，统一存放在项目根目录的 `operation_docs/` 大文件夹中。**

样式权威源：`operation_docs/templates/操作文档编写参考模版.docx`（内容实例：图片任务操作手册）。观感样式以该模版为准；编写规则（编号/枚举/禁忌）以本文件 §3 为准——模版自身 5 项瑕疵已在 OD14 列为反例，不作为编写依据（引用规则 W01，消除双权威冲突）。

## §2 流水线概览

```
Explorer（页面探索） → Planner（编写计划） → Writer（文档编写） → Reviewer（评审）
```

| 阶段 | 一句话职责 |
|------|-----------|
| Explorer | 通过 Playwright 进入目标页面，截图并分析页面结构、功能模块、交互元素 |
| Planner | 基于探索结果和用户输入的功能点，生成编写计划（大纲 + 截图点位清单），用户确认后放行 |
| Writer | 按 OD01-OD14 编写 Markdown 源，每步配截图，再生成 docx |
| Reviewer | 脚本评分（≥85 通过）+ §4 检验清单逐项核验 |

### §2.1 目录结构

```
operation_docs/
├── templates/                          # 模板（不要随意改动）
│   ├── 操作文档编写参考模版.docx        # 唯一样式权威源（内容实例：图片任务操作手册）
│   ├── operation_doc_template.md       # Markdown 主模板（章节结构对齐 docx）
│   └── operation_doc_plan_template.md  # 编写计划模板
├── markdown/                            # Markdown 源文件
│   └── {功能名}.md
├── docx/                                # docx 渲染版本（最终交付）
│   └── {功能名}.docx
├── screenshots/                         # 截图（按功能分子目录）
│   └── {功能名}/
│       ├── 00-流程图.png
│       ├── 01-{字段1}.png
│       └── ...
└── {功能名}-评审报告.md                 # 评审产出
```

### §2.2 意图识别规则

- "写操作文档" / "写操作手册" / "写使用手册" / "写用户指南" → doc
- "给XX功能写操作说明" → doc
- "截图写操作步骤" / "按页面截图写文档" → doc
- "整理XX的操作流程文档" → doc

## §3 编写规则明细（OD01-OD14）

> 规则 OD01-OD14 是《操作文档编写参考模版.docx》的文字化判定式。Writer 编写时逐条执行；Reviewer 按 §4 检验清单逐项核验。

### §3.1 权威源与文档头

**OD01 模版权威源**：`operation_docs/templates/操作文档编写参考模版.docx` 为唯一样式权威源。章节结构、表格列序、编号格式观感以该模版实际呈现为准；与本文件规则冲突时以本文件为准（模版瑕疵见 OD14 反例）。模版文件禁止改动、禁止另存副本（引用规则 W01）。

**OD02 文档头（固定 4 行）**：Markdown 源文档首部固定依次出现以下 4 行，缺一不可：

| 行序 | 内容 | 格式判定 |
|------|------|----------|
| 1 | `# 【{功能名}】` | H1 标题，方括号包裹功能名 |
| 2 | `更新时间：YYYY-MM-DD` | 日期为本次编写/更新日期 |
| 3 | `有疑问可咨询产品经理@{负责人}` | 负责人写花名或英文名（如 `@VitoMa`） |
| 4 | `持续更新中....` | 固定文案，末尾 4 个英文句点 |

### §3.2 章节与编号体系

**OD03 章节体系**：

| 层级 | 格式 | 枚举/序列 |
|------|------|-----------|
| 章（`##`） | 中文数字 + 顿号 | 固定序列 `一、功能介绍` → `二、{主功能}-操作说明` → `三、{次功能}-操作说明`（可选，联动 OD11）→ `四、常见问题` |
| 操作条目（`###`） | 阿拉伯数字 + 顿号 | `1、{操作名}`，章内从 1 连续递增 |

- 「二、」章标题中 `{主功能}` 替换为实际功能模块名（如模版实例「二、设计任务-操作说明」）
- 禁止出现四级标题（`####`）；全文标题层级 ≤ 3 级（`#` / `##` / `###`）

**OD04 正文编号**：

| 编号形态 | 格式 | 示例 |
|----------|------|------|
| 操作要点 | `{条目号}.{要点序号}` | `2.1`、`2.2`，从 1 连续递增 |
| 子要点 | `{条目号}.{要点序号}.{子序号}` | `5.2.1`，三级封顶，禁止四级 |
| 枚举子项 | 半角数字 + 全角右括号 | `1）2）3）` |

- 编号必须**连续且唯一**：禁止跳号（反例：模版 16 后直接 19）、禁止重号（反例：模版两个 6.2）
- 编号后直接接正文，不加空格（对齐模版实例 `1.1用于创建…`）

### §3.3 第一章「功能介绍」内容规则

**OD05 简介（`### 1、简介`）**：

- `1.1` 固定为核心用途：功能是什么 + 谁使用 + 解决什么问题（一句话到三句话）
- `1.2` ~ `1.N-1` 为子功能/分类说明，每点一个分类（模版实例：1.2 设计任务、1.3 非设计任务）
- 末位 `1.N` 固定为数据查询权限，权限规则用 `1）2）` 枚举；无权限控制时固定写「无数据权限控制，登录用户全量可见」，禁止省略该点

**OD06 涉及角色（`### 2、涉及角色`）**：使用无序列表，每行一个角色，格式 `- {角色名}：{一句话职责}`；角色名与系统内岗位/权限命名一致；只列本功能实际涉及的角色。

**OD07 流程图（`### 3、流程图`）**：

- 先用 Mermaid `flowchart` 语法编写流程图源码（权威源），以 ` ```mermaid ` 代码块保留在 Markdown 源文件中
- 用 `generate_diagram` 生成到 FigJam，`get_screenshot`（maxDimension=2000）导出 PNG，curl 下载为 `operation_docs/screenshots/{功能名}/00-流程图.png`
- 嵌入引用 `![{功能名}操作流程](../screenshots/{功能名}/00-流程图.png)`
- docx 为《交互式流程图标准》显式例外：PNG 仅作 docx 呈现，Mermaid 源码仍为权威源（见 `docs/rules/flow-diagram-standard.md` 适用范围）

### §3.4 第二章「操作说明」内容规则

**OD08 操作条目三段式**（`二、` 章下每个 `###` 条目按以下结构组织要点）：

| 要点位 | 内容 | 判定要求 |
|--------|------|----------|
| `X.1` | 前置条件 | 什么状态/什么角色可执行本操作；状态值用反引号（如 `待处理`）；无前置条件固定写「无前置条件」 |
| `X.2` ~ `X.N-1` | 用途与动作说明 | 每点讲一个动作或一条规则；提及界面按钮/区域时必须配截图（OD13） |
| `X.N` | 结果与状态流转 | 操作后的结果，状态变化写 `{原状态}` → `{新状态}` |

- 条目排列顺序：按列表页操作区从左到右，或业务流程先后；批量操作固定放最后（OD10）

**OD09 字段维护详情表**：操作条目含表单/字段维护时，在要点后紧跟一行 `X.Y 字段维护详情`，再插表格：

| 规则项 | 判定式 |
|--------|--------|
| 列结构 | 固定 4 列：`字段/操作 \| 是否必填 \| 说明 \| 截图`，列序不可换 |
| 行序 | 字段按页面表单从上到下排列 |
| `是否必填` | 枚举封死 = `是` / `否`；禁止空值、禁止「选填」等变体；条件必填填 `是` 并在说明列注明触发条件（引用规则 W07） |
| `说明` | 多点用 `1、2、3、` 编号列点，表格内换行用 `<br>`；子点用 `X.Y` 编号（如 `2.1`） |
| `截图` | **必填字段截图列不得空缺**（嵌入字段区域截图）；非必填字段允许空缺；引用格式 `![](../screenshots/{功能名}/{NN}-{字段名}.png)` |

**OD10 批量操作表**：列表页存在批量操作区时，设独立条目 `### {N}、批量操作`，固定 3 列：`功能 | 说明 | 截图`；`说明` 列写法同 OD09（`1、2、` 列点 + `<br>` 换行）；`截图` 列每行不得空缺（截操作入口或结果弹窗）；无批量操作功能时不设此条目。

### §3.5 第三、四章内容规则

**OD11 次功能章（`## 三、{次功能}-操作说明`，可选）**：存在时结构与「二、」章完全一致（OD08-OD10 同样适用）；无可写内容时**整章删除（含章标题）**，禁止只留空标题。

**OD12 常见问题（`## 四、常见问题`）**：每个问题结构如下；章为固定末章，无已知问题时保留章标题并写一行固定兜底文案「暂无常见问题，使用中如有疑问请联系产品经理@{负责人}」，禁止留空章。

```
### Q{N}：{问题一句话}

**问题描述**：{现象/触发场景}

**解决方法**：

1. {步骤1}
2. {步骤2}
```

### §3.6 截图规则

**OD13 截图命名与标注**：

| 规则项 | 判定式 |
|--------|--------|
| 命名 | `{NN}-{名称}.png`，NN 为两位数字、从 `01` 起按文档引用顺序连续递增；名称取操作名或字段名（如 `01-商品详情.png`），禁止无名或纯数字 |
| `00-` 号段 | 保留给流程图（OD07），页面截图禁止使用 `00-` 前缀 |
| 存放 | `operation_docs/screenshots/{功能名}/` |
| 标注 | 每提及一个按钮/操作区域/字段区域，截图中对应位置必须用红框或箭头标出 |
| 采集 | 线上页面用 Playwright；本地原型用预览截图（Playwright / http.server） |

### §3.7 编写禁忌

**OD14 禁忌清单**（模版 5 项瑕疵作反例，Writer 交付前逐条自查）：

| # | 禁忌 | 模版反例 |
|---|------|----------|
| 1 | 禁止编号跳号/重号（OD04） | 模版 16 后直接 19；两个 6.2 |
| 2 | 禁止空内容条目：`###` 标题下必须至少有 1 个要点或 1 张表 | 模版 19-23 仅有标题无内容 |
| 3 | 禁止「是否必填」空值/变体（OD09） | 模版多行空值 |
| 4 | 禁止错别字/病句：交付前通读校对一遍 | 模版「确认要求确认情况查看」 |
| 5 | 禁止占位符 `{...}` 残留 > 5 处（通过线见 `docs/verification/quality-gates.md` §2.4） | — |
| 6 | 禁止页面截图占用 `00-` 号段（OD13） | — |

## §3.8 执行流程

1. **初始化目录**：`python3 scripts/operation_doc_manager.py init --feature {功能名}`（自动创建 `operation_docs/screenshots/{功能名}/`）
2. **创建 Markdown 骨架**：`python3 scripts/operation_doc_manager.py create --feature {功能名} --author {作者} --version {版本号}`（从 `operation_docs/templates/operation_doc_template.md` 复制到 `operation_docs/markdown/{功能名}.md`）
3. **页面探索（Explorer）**：用户提供页面 URL 或本地原型 HTML；用 Playwright 导航到目标页面；截取关键页面截图（首页、列表页、详情页、弹窗为基线四类，完整点位以 Planner 截图点位清单为准）；按 OD13 命名保存
4. **生成操作流程图**：按 OD07 执行（Mermaid 权威源 → FigJam → PNG → `00-流程图.png`）
5. **功能点收集**：用户提供功能点和操作流程说明；或基于页面探索自动识别功能点，与用户确认
6. **生成编写计划（Planner）**：从 `operation_docs/templates/operation_doc_plan_template.md` 生成大纲（对齐 OD03 章节序列）+ 截图点位清单（标注必填字段点位）
7. **用户确认计划**：展示编写计划，等待用户确认或修改；确认信号判定引用规则 W14；确认后才进入 Writer 阶段
8. **文档编写（Writer）**：按 OD01-OD14 逐条编写 `operation_docs/markdown/{功能名}.md`，每步配对应截图
9. **生成 docx**：`python3 scripts/operation_doc_manager.py generate-docx --feature {功能名}`（输出 `operation_docs/docx/{功能名}.docx`，含截图嵌入、表格、标题样式）
10. **评审（Reviewer）**：`python3 scripts/operation_doc_manager.py review --feature {功能名}`（输出 `operation_docs/{功能名}-评审报告.md`）+ §4 检验清单逐项核验；不通过则返工，最多 2 次（引用规则 W20）

## §3.9 评审细则

- 评分维度与通过线：权威定义见 `docs/verification/quality-gates.md` §2.4（满分 100，≥85 通过），本文件不重述（引用规则 W01）
- 脚本自动评分覆盖 4 维度；§4 检验清单覆盖 OD 规则逐项核验，两者均执行
- **流程图检查**：确认 `00-流程图.png` 存在、由 Mermaid 权威源生成（非页面截图），且 Mermaid 源码保留在 Markdown 源文件中（OD07）
- **docx 同步**：改内容必须改 Markdown 重新生成 docx，禁止手工改 docx

## §4 检验清单

> Reviewer 逐项执行；机器可验项给出检查命令（项目根目录执行，`<md>` = `operation_docs/markdown/{功能名}.md`），标注口径引用规则 W21。

| # | 检验项 | 关联规则 | 类型 | 检查方法 |
|---|--------|----------|------|----------|
| 1 | 文档头 4 行齐全 | OD02 | 【机器可验】 | `grep -c "更新时间：\|有疑问可咨询产品经理@\|持续更新中" <md>` = 3，且首行匹配 `^# 【.+】$` |
| 2 | 章节序列齐全有序 | OD03 | 【机器可验】 | `grep -nE "^## 一、\|^## 二、\|^## 四、" <md>` 命中 3 行且行号递增 |
| 3 | 操作条目编号连续 | OD03 | 【机器可验】 | `grep -oE "^### [0-9]+、" <md> \| grep -oE "[0-9]+"` 输出为连续自然数列 |
| 4 | 无四级标题 | OD03 | 【机器可验】 | `grep -c "^####" <md>` = 0 |
| 5 | 要点编号无重号/跳号 | OD04 | 【人工判定】 | 抽读全文 `X.Y` 编号序列（脚本辅助：`grep -oE "^[0-9]+\.[0-9]+" <md> \| sort` 查重） |
| 6 | 字段表 4 列且列序正确 | OD09 | 【机器可验】 | `grep -n "字段/操作" <md>` 命中行均为 `| 字段/操作 | 是否必填 | 说明 | 截图 |` |
| 7 | 是否必填仅 `是`/`否` | OD09 | 【机器可验】 | 脚本提取字段表第 2 列，值集合 ⊆ {是, 否} |
| 8 | 必填字段截图列无空缺 | OD09 | 【人工判定】 | 逐行核对「是否必填 = 是」的行截图列有 `![](...)` 引用 |
| 9 | 批量操作表 3 列 | OD10 | 【机器可验】 | `grep -n "功能 | 说明 | 截图" <md>` 命中行列为 3（无批量操作条目时豁免，人工确认） |
| 10 | 流程图合规 | OD07 | 【机器可验】 | `test -f operation_docs/screenshots/{功能名}/00-流程图.png` 且 `grep -c '```mermaid' <md>` ≥ 1 |
| 11 | 页面截图未占用 00- 号段 | OD13 | 【机器可验】 | `ls operation_docs/screenshots/{功能名}/00-* \| wc -l` = 1（仅流程图） |
| 12 | 截图编号连续递增 | OD13 | 【机器可验】 | `ls operation_docs/screenshots/{功能名}/` 文件名 NN 段连续无跳号 |
| 13 | 截图关键位置红框标注 | OD13 | 【人工判定】 | 逐图核对按钮/区域有红框或箭头，文字清晰可读 |
| 14 | 无空内容条目 | OD14 | 【人工判定】 | 抽查每个 `###` 标题下至少有 1 个要点或 1 张表 |
| 15 | 占位符残留 ≤ 5 处 | OD14 | 【机器可验】 | `grep -oE "\{[^}]+\}" <md> \| wc -l` ≤ 5 |
| 16 | docx 已生成且晚于 Markdown | §3.9 | 【机器可验】 | `test -f operation_docs/docx/{功能名}.docx` 且 docx mtime ≥ md mtime |
| 17 | 评审评分 ≥ 85 | §3.9 | 【机器可验】 | `test -f operation_docs/{功能名}-评审报告.md` 且报告内评分数值 ≥ 85 |

## 交付物

- `operation_docs/markdown/{功能名}.md` — Markdown 源（权威内容源）
- `operation_docs/docx/{功能名}.docx` — docx 最终交付（严格对齐 `操作文档编写参考模版.docx` 样式）
- `operation_docs/screenshots/{功能名}/*.png` — 操作截图
- `operation_docs/{功能名}-评审报告.md` — 评审报告
